# 实体名称规则（Team / Agent 名称）

> 名字会直接拼进文件路径，约束是「能安全当目录名」。校验实现：`src/util/workspaceUtil.py::validate_dir_name`。第 1 节是规则（从上到下依次短路判定），后面几节是规则之外的其它注意点。只禁止会影响路径安全的字符，其余（含 emoji、任意 Unicode）一律放行。

## 1. 规则

| # | 规则 | 通过 ✅ | 不通过 ❌ |
|---|------|---------|-----------|
| 1 | 必须是字符串 | `"alice"` | `123`、`None` |
| 2 | 不能为空 | `"a"` | `""` |
| 3 | 首尾不能有空白（`name != name.strip()`，覆盖全角空格、Tab、换行） | `"alice"`、`"a b"`（中间空格允许） | `" alice"`、`"　alice"`（全角空格） |
| 4 | 不能是 `.` 或 `..`（整串等于） | `"a..b"`、`"alice.txt"` | `.`、`..` |
| 5 | 不能是 Windows 保留名（取第一个 `.` 前的主干，`upper()` 后等于保留名） | `"CON1"`、`"myCON"`、`"alice.txt"` | `CON`、`con`、`NUL`、`com1`、`CON.txt`、`NUL.abc` |
| 6 | 不能包含路径分隔符 / Windows 非法字符 / 控制字符 | `"😀"`、`"="`、`"a b"`、`"产品经理"` | `a/b`、`a\b`、`a:b`、`a*b`、`a\x00b` |

> 规则 6 的黑名单字符：`/` `\` `:` `*` `?` `"` `<` `>` `|` 以及控制字符（含 NUL）。保留名集合：`CON`、`PRN`、`AUX`、`NUL`、`COM1~9`、`LPT1~9`。

> ⚠️ 规则 4 是删除级风险：名叫 `..` 的成员离职时会执行 `rmtree(agent/..)`，直接清空整个团队目录。

## 2. 文件系统大小写

- macOS（APFS 默认大小写不敏感）：`Alice` 与 `alice` 是**同一个目录**，会互相覆盖。
- Linux（ext4）大小写敏感：二者是两个不同目录。
- 影响：同团队建 `Alice` + `alice` 会共享目录；在岗成员目录可能被当离职成员误删；仅改大小写 rename（`alice` → `Alice`）在 macOS 上永远失败。
- 现状：未做大小写判重（待跟进）。

## 3. 长度限制

- macOS（APFS）按 UTF-16 码元 ≤ 255；Linux（ext4）按 UTF-8 字节 ≤ 255，跨平台安全上限取更严的 **UTF-8 字节 ≤ 255**（如 `'中' * 255` = 765 字节，macOS 能过、Linux 会失败）。
- 现状：`validate_dir_name` 不校验长度，超长名会在 `os.makedirs` 处裸抛 OSError（待跟进）。

## 4. Unicode 归一化 / 全角半角

- 全角 `Ｆ` 与半角 `F` 是两个不同目录，用户看不出区别。
- NFD 组合字符（`José` 的 NFD 写法）在不同平台校验结果不一致。
- 建议：存库前 `unicodedata.normalize("NFC", name)`（待跟进）。

## 5. Windows 保留名 + 扩展名

- Windows 上「保留名 + 扩展名」仍是保留名（`CON.txt`、`NUL.abc` 都非法）。
- 所以规则 5 取第一个 `.` 前的主干再比对：`CON.txt` 主干是 `CON`，命中即拒绝；`CON1.txt` 主干是 `CON1`，放行。
