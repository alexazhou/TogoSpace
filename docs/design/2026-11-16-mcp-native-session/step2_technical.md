## 1. 运行环境与依赖约束

MCP 使用 Python MCP SDK，在后端现有 asyncio 循环中运行，客户端 session 不增加独立 daemon 进程。stdio MCP server 是外部程序，其所属子进程仍按协议需要启动和清理。

mcporter 用于参考 CLI 语法，引入其 TypeScript runtime 或移植解析器尚未决定。需要遵守 [产品文档的 CLI 契约](./step1_product.md#2-cli-命令与示例)，具体解析方案待设计。

## 2. 现有能力复用与职责约束

| 职责 | 技术约束 |
|---|---|
| 命令解析与路由 | 保留执行框架的权限校验和可信调用上下文；不能因为接入另一套命令解析绕过鉴权 |
| 服务配置读写 | 复用已有全局 server 注册数据及配置管理能力；CLI、设置页和 HTTP 接口使用同一数据来源 |
| 连接管理 | session 及连接由有状态服务管理，统一承担连接获取和释放；具体服务落点、接口和并发策略待设计 |
| 协议调用 | 通过 Python MCP SDK 执行协议操作，复用 SDK 数据对象及序列化能力 |
| 结果转换 | 适配 console 工具返回接口，复用结果序列化及错误处理；不能为调用方便手工拼装重复模型字段 |

遵守 controller / service / dal / model / util 的依赖方向，持久配置与运行连接状态各自承担相应职责。具体模块依赖和接口定义在完整技术方案中补齐。

## 3. 身份与资源归属

`(team_id, agent_id)` 来自可信调用上下文，是活动 session 的归属标识。CLI 参数不能覆盖调用者身份，缺少有效身份时不能回退为全局 session。

连接归属必须包含 Agent 身份，不能仅以 server 名称、URL 或等价配置作为跨 Agent 连接池的复用依据。单个 session 下各 server 连接的具体标识与配置快照规则尚未确定。

[产品文档 §3](./step1_product.md#3-无名称跨-server-的-session) 定义 session 行为，技术设计需要明确谁持有连接、谁负责关闭以及如何处理初始化中的连接。stdio server 子进程随所属连接回收；不能把客户端 session 结束仅处理为移除一条本地记录。

生命周期清理须覆盖创建中的连接与已经建立的连接。SDK 上下文归属、初始化与停止的竞态、取消以及异常清理方式仍需设计。远端账号级状态不属于本地连接隔离能够保证的范围。

## 4. 宿主接口与输出适配

CLI 调用通过 console 工具接口接收命令和返回结果，不读取后端 stdin，也不执行 shell 管道或重定向。上游使用 stdout / stderr 或退出码的路径需适配为工具结果，不能结束后端进程。

沿用应用调用期限、20,000 字符输出限制和凭证脱敏。截断需要标识，失败需要返回真实原因；具体输出对象及支持格式遵循产品契约。需要人工输入的授权不能阻塞等待后端终端输入。

不自动重放结果未知的业务调用。超时、取消与停止时的资源回收及错误处理策略，需要在实施前补齐。
