# 私聊消息立即注入与顺序简化 - 产品文档

> 关联文档：[技术设计](./step2_technical.md)

## 1. 背景与目标

V20（运行中上下文插入）与 V21（监督指令与控制房间）上线后，操作者可以在私聊房间向正在工作的 Agent 发送「普通排队消息」或「立即注入消息」，也可以将排队中的普通消息升级为立即注入。

但现有机制把「消息顺序」与「Agent 是否已读取」耦合在同一状态上（未读取的消息不分配序号），导致三类体验与稳定性问题：

1. **先发后至（乱序）**：操作者先发一条普通消息、再发一条立即注入消息时，立即注入消息会排到普通消息前面，破坏真实发言顺序。
2. **跨房间督导失效**：当 Agent 正在处理群聊或协作任务（`TODO_TASK`）时，其私聊控制房间本身处于空闲（`IDLE`），此时通过活动面板发送督导指令会被降级为普通消息，无法在当前工作步骤中即时生效，或者在 Agent 空闲时发送立即注入指令反而无人唤醒。
3. **状态机繁琐脆弱**：普通排队、立即注入、中途升级三套路径各自维护序号与可见性，边界场景容易卡死。

本次简化的核心目标：

- **所见即所发**：所有消息发出即按真实先后顺序编号，彻底消除乱序。
- **立即注入连带收取**：立即注入消息在安全边界触发提前读取时，自动连带收取排在它前面的未读普通消息，既及时响应又不乱序。
- **全场景督导一致**：无论 Agent 当前正在私聊、群聊、协作任务中工作，还是处于空闲状态，发往私聊控制房间的立即注入指令都能稳定生效。

## 2. 核心规则

### 2.1 消息类型与触发时机（仅私聊房间）

私聊房间中，操作者发送的消息分为两类：

| 消息类型 | 触发读取时机 | 典型入口 |
|---|---|---|
| **普通消息**（`insert_immediately=False`） | 等 Agent 当前轮次（Turn）结束后，在下一轮开始时读取；若房间当前空闲则立即唤醒新一轮 | 私聊聊天框直接发送 |
| **立即注入消息**（`insert_immediately=True`） | 在 Agent 当前工作的**安全边界**（当前推理或整批工具调用完成后）提前读取；若房间当前空闲则立即唤醒新一轮 | Agent 活动视图「督导」发送、或在私聊浮动栏点击「立即引导」 |

> **群聊房间保持不变**：群聊不支持立即注入与排队展示，所有消息按正常轮次流转。

### 2.2 严格保序与连带收取

1. **发送顺序固定**：消息一旦发出，其在房间内的先后顺序即固定，后续升级为立即注入或被 Agent 读取均不改变顺序。
2. **连带收取**：当房间内存在未读的立即注入消息并在安全边界触发 Agent 提前读取时，系统会将该房间内**当前所有尚未被 Agent 读取的消息（含排在该立即注入消息之前或之后的未读普通消息）一并按顺序交给 Agent**。

```text
场景 A（先普通后立即注入）：
操作者先发普通消息 M1：「顺便看下日志格式」
操作者再发立即注入消息 M2：「先停一下，优先检查 stderr」
→ 安全边界到达时，Agent 按 [M1, M2] 顺序一次性收到两条消息

场景 B（升级中间消息）：
操作者连发普通消息 M1、M2，随后对 M1 点击「立即引导」升级为立即注入
→ 安全边界到达时，Agent 按 [M1, M2] 顺序将当前未读消息一次性收齐
```

### 2.3 中途升级（「立即引导」）

- 当 Agent 正在工作、操作者发送的普通消息尚未被 Agent 读取时，该消息展示在聊天窗底部的浮动待读区（显示「⏳ 排队中」）。
- 操作者可点击「立即引导」将其升级为立即注入消息（状态变为「⚡ 即将注入」），在下一个安全边界提前交给 Agent。
- 若消息在点击时已被 Agent 读取，则提示无法升级。

### 2.4 跨房间督导与空闲唤醒

- **Agent 正在跑群聊或协作任务**：操作者向私聊控制房间发送立即注入消息（或升级普通消息为立即注入），Agent 会在当前群聊/任务的下一个安全边界立即读到该消息。
- **Agent 当前完全空闲**：操作者向私聊控制房间发送立即注入消息，系统直接唤醒 Agent 开启新轮次处理，不会停留在待注入状态。

## 3. 界面展示规则（私聊房间）

私聊房间中，**仅操作者（Operator）发送的消息**根据「Agent 是否已读（`unread`）」与「是否立即注入（`insert_immediately`）」展示四种状态；**Agent 自己的回复与系统消息**始终直接显示在主消息流中，不显示待读状态。

| 状态 | 条件（仅限私聊 Operator 消息） | 展示位置 | 标记 |
|---|---|---|---|
| **排队中**（`queued`） | 普通消息 && Agent 未读 | 底部浮动待读区 | `⏳ 排队中`（可点击「立即引导」） |
| **即将注入**（`pending-immediate`） | 立即注入消息 && Agent 未读 | 底部浮动待读区 | `⚡ 即将注入` |
| **已立即注入**（`immediate`） | 立即注入消息 && Agent 已读 | 主消息流 | `⚡` |
| **普通已发布**（`published`） | 普通消息 && Agent 已读（以及全部 Agent/系统消息、群聊消息） | 主消息流 | 无额外标记 |

一旦 Agent 读取了浮动待读区的消息，这些消息立即按原有顺序移入主消息流，浮动区自动收起。

## 4. 产品边界

### 本次包含
- 消息发送即固定顺序，消除先发后至乱序
- 立即注入消息在安全边界触发时，连带收取排在前面的未读消息
- 私聊房间未读/已读状态改由 Agent 真实读取进度驱动
- 修复跨房间（群聊/协作任务进行中）及 Agent 空闲时发送立即注入指令的生效问题

### 本次不包含
- 多人群聊房间的立即注入能力
- 非 `host_managed_turn_loop` 驱动模式的运行中插入
- 强制中断正在执行的单个工具调用（仍遵循安全边界约束）

## 5. 验收标准

- [ ] **顺序一致**：私聊中连续发送普通消息与立即注入消息，消息顺序严格等于发送顺序，不再出现后发的立即注入消息排到前面。
- [ ] **连带收取**：私聊中先发普通消息 M1、再发立即注入消息 M2，Agent 在当前轮次安全边界按 `[M1, M2]` 顺序一次收齐。
- [ ] **普通排队不丢轮**：私聊中仅发送普通消息（无立即注入），Agent 在当前轮次执行期间不提前读取，当前轮次一结束立即开启下一轮读取并回复。
- [ ] **中途升级**：对未读普通消息点击「立即引导」，消息保持原顺序变为「即将注入」，并在安全边界被提前收取；对已读消息升级则报错拒绝。
- [ ] **跨房间与空闲督导**：Agent 在执行群聊轮次、协作任务轮次或处于空闲状态时，通过活动面板发送督导指令均能正常被 Agent 收取，不降级、不卡死。
- [ ] **展示范围准确**：仅私聊中的 Operator 消息会出现「排队中 / 即将注入」浮动条；Agent 自身回复、系统消息及群聊消息均直接显示在主消息流中。
