# 设计文档规范

## 目录结构

```
docs/design/
├── 设计文档规范.md       # 本文件，记录设计与文档命名规范
├── ROADMAP.md            # 实施路线图（发布版本概览 + 相关文档索引）
├── 2026-03-05-dual-agent-single-room/           # 里程碑：双 Agent 单房间
├── 2026-03-05-multi-agent-single-room/          # 里程碑：多 Agent 单房间
└── ...
```

设计文档**按里程碑/功能主题组织，目录名为 `{date}-{feature}`**，不再按版本号划分目录。日期取该功能落地的版本发布（tag/commit）日期，如 `2026-03-05` 对应 V1 的落地日期。

## 文档命名规范

### 目录命名

每个里程碑/功能一个子目录，采用 `{date}-{feature}` 格式，feature 用 kebab-case 英文主题（如 `agent-multimodal-support`、`deepseek-search-service`）。

### 步骤文档

每个里程碑内按开发流程顺序编写，文件名**不带版本号前缀**，步骤可按需取舍：

| 文件 | 文档类型 | 说明 |
|------|---------|------|
| `step1_product.md` | product | 产品文档：目标、功能特性、对话示例/交互、验收标准、使用说明 |
| `step2_technical.md` | technical | 技术文档：架构设计、接口定义、模块依赖、技术要点 |
| `step3_tasks.md` | tasks | 开发任务表：任务拆分、依赖关系、复用说明、测试检查清单（未完成功能必写） |

### 专项设计与改动方案文档

- **专项设计/技术重构/改动方案**（如改名、模块拆分、三方搜索集成、导入导出等），随所属里程碑或日期放入对应目录，命名采用 `{feature}_design.md` 或 `{feature}_plan.md`。
- **示例与辅助资料**，可在该里程碑目录下建立子目录（如 `examples/`）存放。

## 新增功能流程

1. 在 `docs/design/` 下创建子目录 `{date}-{feature}/`（日期用功能立项/落地的发布日期，进行中可用当前日期并在 ROADMAP 标注状态）
2. 按顺序编写文档：`step1_product.md` → `step2_technical.md` → `step3_tasks.md`（或专项设计文档）
3. 在 `ROADMAP.md` 的“版本概览”或功能列表中补充对应条目，并在“相关文档”章节添加索引链接
