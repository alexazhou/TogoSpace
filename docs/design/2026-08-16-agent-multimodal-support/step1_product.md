# V25: Agent 多模态请求支持 - 产品文档

## 目标

让 Agent 的对话从"只处理文字"升级为"能处理图片"——支持**多模态请求**，即对话消息中除文字外，还可以携带图片内容。图片内容有两个来源方向：

1. **工具返回的图片**：Agent 调用工具（执行命令、截屏、读取文件等）时，工具返回的图片结果可以回传给模型识别。**（V25 落地）**
2. **用户发送的图片**：用户在对话中直接发送给 Agent 的图片，Agent 能"看到"并理解。**（方向已确定，入口链路延后到后续版本）**

V25 先打通"工具返回图片 → 模型识别"这条链路，为多模态能力打下基础；用户发图作为既定的后续方向，依赖房间消息模型与接口的扩展。

---

## 核心概念

### 1. 多模态消息

一条对话消息可以同时包含文字和图片，Agent 能理解其中的内容，而不只是纯文本。

### 2. 工具结果图片（V25）

Agent 在执行任务过程中调用工具产生的图片（如命令执行截图、结果图片、读取到的图片文件），能作为上下文回传给模型，让 Agent 对执行结果"眼见为实"。

### 3. 用户输入图片（后续方向）

用户在对话中直接发送的图片，作为本轮任务的一部分交给 Agent。此链路涉及房间消息模型与发消息接口的扩展，V25 不实现。

---

## 用户场景

### 场景一：工具返回图片，Agent 自行判断（V25）

Agent 执行一个会产生截图 / 图片结果的工具（如运行脚本、打开页面截图）。

- 期望：返回的图片能回传给模型，Agent 基于截图内容自我校验、继续行动或向用户说明结果。

### 场景二：用户发图给 Agent（后续版本）

用户给 Agent 发一张图片并附带要求，如"这张图里有什么"、"根据这张图整理一份报告"。

- 期望：Agent 能基于图片内容给出符合要求的回复或行动。此场景依赖用户图片入口链路，V25 暂不覆盖。

---

## 功能特性

1. **工具结果图片回传模型**：工具返回的图片能进入 Agent 的对话上下文，供模型识别。
2. **图片随历史持久化**：图片随对话历史保存，Agent 重启 / 恢复后上下文不丢失。
3. **与文字对话无缝共存**：纯文字对话行为保持不变，图片只是对现有能力的扩展。

---

## 产品边界

### V25 包含

- 工具返回的图片进入 Agent 对话上下文并回传给模型识别。
- 图片随历史持久化，重启恢复后上下文不丢。
- 发送格式遵循 OpenAI 多模态规范，兼容支持视觉的主流模型。
- 多模态消息类型与转换的基础能力（为后续用户图片、多模态响应等扩展留好地基）。

### V25 不包含

- **用户发送图片的入口链路**（房间消息模型增加图片承载、发消息接口与同步链路改造）——延后到后续版本。
- 前端上传图片的界面交互（Web / TUI 端图片选择、预览）。
- 图片生成 / 编辑能力。
- 模型回传图片（多模态响应）的存储与展示。
- 视频 / 音频等多模态内容。

---

## 验收标准

- [ ] 工具返回图片时，图片能回传模型，Agent 能基于图片内容继续行动。
- [ ] 含图片的对话在 Agent 重启后仍能恢复上下文。
- [ ] 纯文字对话行为与改造前一致，不受影响。
- [ ] 图片消息的发送格式符合 OpenAI 多模态规范，能兼容支持视觉的主流模型。

---

## 使用说明（用户视角）

- **Agent 看图自检**：当 Agent 使用会返回截图 / 图片的工具时，模型会结合图片内容判断结果并推进任务，无需用户额外转述。
- **用户直接发图**：属后续版本能力，V25 暂不支持用户向 Agent 直接发送图片。
