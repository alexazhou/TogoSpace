# Agent 图片视觉 Fallback（视觉模型兜底）- 产品文档

> 状态：规划中（尚未实施）

## 背景与问题

V25 已完成 Agent 多模态请求支持：`read_image` 工具（TSP）返回图片 base64 + 元数据，host 侧把图片以独立 USER 图片消息（data URL）随请求发送给模型。

但存在一个关键问题：**主模型可能不支持视觉**。

- 当前 agent 配置的推理模型（如 DeepSeek-V4-Flash）未必具备图片理解能力。
- 直接把图片消息发给不支持视觉的模型，可能：
  - 模型 API 报错（拒绝 image_url content block）；
  - 或模型静默忽略图片内容，agent 无法真正"看图"。

## 目标

当 agent 本轮上下文包含图片时，按以下策略自动处理：

| 场景 | 处理 |
|------|------|
| 主模型支持视觉（`input` 含 `image`） | 正常把图片随 USER 消息发给主模型 |
| 主模型**不支持**视觉，但已配置**视觉模型槽位**（`default_models.vision`） | 自动 fallback：用视觉模型识别图片，将识别结果（文本）注入上下文，主模型继续推理 |
| 主模型**不支持**视觉，且**未配置**视觉模型 | 提示 agent：收到图片，但当前模型不支持视觉，无法读取图片内容 |

## 功能特性

### 1. 图片能力判断（发送前门控）

在 llmService 将 AgentMessage 转换为 OpenAIMessage（发送给模型）时，检测本轮上下文是否包含图片（USER 图片消息 / attachment），并按模型能力分支：

- 无图片 → 正常调用主模型（现有流程不变）。
- 有图片 → 判断主模型是否支持视觉（`resolve_model(agent.model)` 返回的 `input` 含 `image`），进入对应分支。

> 复用现有 `LlmModelConfig.input` 能力字段，不新增配置字段。

### 2. 主模型支持视觉 → 正常发送

主模型支持视觉时，图片随 USER 消息发给主模型，完全复用 V25 多模态流程，无额外行为。

### 3. 主模型不支持视觉 + 已配置视觉模型 → 自动 fallback 识别

主模型不支持视觉但 `default_models.vision` 槽位已配置时：

- agent 业务层（agentService）自动调用视觉模型识别图片（输入：图片 + 简短提示词，不携带完整对话历史，省 token、聚焦识别）。
- 识别结果（纯文本描述）写入该图片附件的说明字段（`MessageAttachment.caption`），并持久化，避免重复识别。
- 发送时转换层发现主模型不支持视觉 + 附件有说明 → 插入该说明文本消息，图片本身不发往主模型 LLM 服务端。
- 多张图片逐张识别（v1 简单可靠）。
- 识别结果做长度限制（约 500 字摘要），避免污染主模型上下文。
- 识别失败（超时 / 报错 / 视觉模型不可用）→ 降级为"无法读取图片"说明，不阻塞 agent 主流程。

> 由开关 `auto_vision_fallback` 控制是否自动兜底，**默认开启**。

### 4. 主模型不支持视觉 + 无图片说明 → 提示 agent

主模型不支持视觉，且图片附件没有说明（未配置视觉模型 / 识别失败）时，转换层向上下文插入明确提示：

> 你收到了一条图片消息，但当前配置的模型不支持视觉（图片识别），因此无法读取图片内容。请忽略该图片，并告知操作者当前模型无法处理图片，或建议配置视觉模型后再重试。

- 目的：让 agent 明确知道"图片存在但读不了"：
  - 不臆造图片内容；
  - 主动向用户/操作者说明限制；
  - 引导用户配置视觉模型或更换模型。
- **每张图片触发一次提示**（v1 按图逐张注入）。

## 非目标

- **不处理除图片外的多模态输入**：音频、视频等不在 v1 范围。
- **不改变主模型选择**：主模型仍负责 agent 推理与工具调用，视觉模型仅做图片识别辅助。
- **识别结果不做结构化输出**：v1 为纯文本描述，不做 JSON 分类/结构化（后续需要再增强）。
- **不新增配置字段**：视觉能力判断与视觉模型配置均复用现有体系（`input` 能力字段 + `vision` 槽位）。
- **不改变前端设置页**：视觉模型槽位配置 UI 保持现状，不额外突出。
- **不污染历史**：图片转文本/插入只影响发送时的 OpenAIMessage，历史中的图片附件始终保留；识别结果写入附件说明字段（`caption`）并持久化。

## 验收标准

- **场景 A**：主模型支持视觉（`input` 含 `image`）时，图片正常随 USER 消息发送，模型可见图片（V25 流程回归通过）。
- **场景 B**：主模型不支持视觉 + 已配置 `default_models.vision`：agent 收到图片后，能基于视觉模型识别文本正确描述图片内容；识别失败时降级为"无法读取"提示，主流程不中断。
- **场景 C**：主模型不支持视觉 + 未配置视觉模型：agent 明确提示"收到图片但模型不支持视觉"，不臆造图片内容。
- **开关**：`auto_vision_fallback=false` 时，场景 B 不触发视觉识别，按场景 C 处理。
- **多张图片**：逐张识别/逐张提示，行为可预期。
- **回归**：无图片的常规对话、V25 多模态（主模型支持视觉）链路不受影响，现有测试全绿。
