# Agent 单聊加急消息（立即注入） - 产品文档

> 关联文档：[技术设计](./step2_technical.md) | 前置设计：[私聊消息立即注入与顺序简化](../2026-11-04-immediate-inject-simplify/step1_product.md)

## 1. 背景与目标

现有系统支持操作者（Operator）在私聊控制房间向 Agent 发送「立即注入消息（`insert_immediately=True`）」，使正在执行任务的 Agent 能在当前轮次（Turn）的**安全边界**（当前推理或整批工具调用完成后）提前读取补充信息，无需等待整个长轮次结束。

但在多 Agent 协作场景下（例如部门主管需要紧急叫停下属正在执行的错误方向、或协作同伴之间需要同步关键阻塞与需求变更），Agent 通过 `send_chat_msg` 发送的消息只能作为普通消息排队，必须等对方当前轮次完全结束后才能在下一轮被读取。

本次设计的目标：

- **开放 Agent 单聊加急能力**：允许 Agent 在调用 `send_chat_msg` 时指定 `insert_immediately=True`，在 **Agent 间单聊房间（`PRIVATE`）** 中触发对方在运行安全边界提前收取消息。
- **行为与体验一致**：Agent 单聊加急消息的保序、连带收取、空闲唤醒、跨房间生效以及前端待读浮动区/标记展示，与操作者私聊立即注入完全一致。
- **非单聊场景优雅降级**：若 Agent 对群聊、对操作者或对不支持运行中注入的驱动模型误传了 `insert_immediately=True`，自动降级为普通消息正常送达并在工具返回中提示说明，不报错中断。

## 2. 核心规则

### 2.1 适用范围与降级规则

Agent 调用 `send_chat_msg` 发送消息时，可通过可选参数 `insert_immediately`（默认 `False`）选择是否加急：

| 目标房间与接收方情况 | `insert_immediately=True` 处理策略 | 工具返回表现 |
|---|---|---|
| **2 人单聊（`PRIVATE`）且对方为支持运行中注入的 AI** | **按立即注入生效**：在对方当前工作的安全边界提前读取；若房间当前空闲则立即唤醒新一轮 | 正常返回送达提示 |
| **多人群聊（`GROUP`）** | **自动降级为普通消息**：按正常轮次流转，不触发提前注入 | 正常送达，附加提示「群聊不支持加急注入，已按普通消息送达」 |
| **与操作者（`OPERATOR`）的单聊房间** | **自动降级为普通消息**：人类无运行中 Turn 循环 | 正常返回送达提示 |
| **对方 AI 驱动不支持运行中注入**（如 `claude_sdk` / `tsp`） | **自动降级为普通消息**：等对方当前轮次结束后在下一轮读取 | 正常送达，附加提示「对方当前驱动不支持运行中加急注入，已按普通消息送达」 |

### 2.2 严格保序与连带收取

与操作者私聊立即注入保持同一套保序与收取规则：

1. **发送顺序固定**：消息发出即按先后顺序分配序号，后续升级或读取均不改变顺序。
2. **连带收取**：当 Agent B 在安全边界检测到与 Agent A 的单聊房间存在未读的立即注入消息时，系统将该单聊房间内**当前所有尚未被 Agent B 读取的消息（含排在该立即注入消息之前或之后的未读普通消息）一并按顺序交给 Agent B**。
3. **跨房间生效与防空转**：
   - 当 Agent B 正在执行群聊轮次或协作任务（`TODO_TASK`）时，Agent A 在单聊房间发出的立即注入消息会在 B 当前工作的下一个安全边界被提前收取，并在提示中注明消息来自该单聊房间。
   - 当 B 结束当前群聊/任务、后续消费到该单聊房间的调度任务时，若消息已在安全边界全部读完且无新消息，自动跳过收尾，不会重复回复或空转。
   - 当 Agent B 当前完全空闲时，Agent A 发送立即注入消息会直接唤醒 B 开启新轮次处理。

```text
场景 A（主管跨房间紧急纠偏）：
1. 下属 Bob 正在执行协作任务（或群聊轮次），编写某模块代码
2. 主管 Alice 在单聊房间 `alice_bob` 调用 send_chat_msg(room_name="alice_bob", msg="接口规范已调整，先暂停旧字段适配", insert_immediately=True)
3. Bob 在当前工具调用结束的安全边界立即收到来自 `alice_bob` 的补充消息，当场调整执行方向
```

### 2.3 中途升级（「立即引导」）

- 在双 Agent 单聊房间中，当 Agent A 发给 Agent B 的普通消息尚未被 Agent B 读取时，同样展示在聊天窗底部的浮动待读区（显示「⏳ 排队中」）。
- 操作者（人类）在围观双 Agent 单聊时，可点击「立即引导」将该未读普通消息升级为立即注入消息（状态变为「⚡ 即将注入」），让 Agent B 在下一个安全边界提前读取。
- 若消息在点击时已被 Agent B 读取，则提示无法升级。

### 2.4 使用准则引导

在系统提示词（System Prompt）与 `send_chat_msg` 工具参数说明中明确约束：
- `insert_immediately=True` **仅用于紧急叫停、方向重大纠偏、关键阻塞同步**等必须让对方在当前行动中立刻看到的场景。
- 日常问答、常规任务派发通知、进度同步及群聊沟通一律保持默认 `False`。

## 3. 界面展示规则（单聊房间统一）

单聊房间（含「操作者 ↔ AI」与「AI ↔ AI」两类单聊）中，**发往 AI 接收方的消息**根据「接收方 AI 是否已读（`unread`）」与「是否立即注入（`insert_immediately`）」统一展示四种状态；**发往操作者（人类）的消息、系统消息及群聊消息**始终直接显示在主消息流中。

| 状态 | 条件（单聊中发往 AI 接收方的消息） | 展示位置 | 标记 |
|---|---|---|---|
| **排队中**（`queued`） | 普通消息 && 接收方 AI 未读 | 底部浮动待读区 | `⏳ 排队中`（可点击「立即引导」） |
| **即将注入**（`pending-immediate`） | 立即注入消息 && 接收方 AI 未读 | 底部浮动待读区 | `⚡ 即将注入` |
| **已立即注入**（`immediate`） | 立即注入消息 && 接收方 AI 已读 | 主消息流 | `⚡` |
| **普通已发布**（`published`） | 普通消息 && 接收方 AI 已读（以及发给操作者的消息、系统消息、群聊消息） | 主消息流 | 无额外标记 |

一旦接收方 AI 读取了浮动待读区的消息，这些消息立即按原有顺序移入主消息流，浮动区自动收起。

## 4. 产品边界

### 本次包含
- `send_chat_msg` 工具支持 `insert_immediately` 参数及非单聊/不支持驱动场景的自动降级
- Agent 在执行任意轮次（私聊、群聊、协作任务）的安全边界自动收取所有单聊房间的未读立即注入消息
- 双 Agent 单聊房间支持中途升级（「立即引导」）、底部浮动待读区与 `⚡` 标记展示
- 双 Agent 单聊房间在轮次结束时的未读尾唤醒精准定位接收方 AI

### 本次不包含
- 多人群聊房间的立即注入能力
- 非 `host_managed_turn_loop` 驱动模式的运行中插入
- 强制中断正在执行的单个工具调用（仍遵循安全边界约束）

## 5. 验收标准

- [ ] **单聊加急生效**：Agent A 在与 Agent B 的单聊房间调用 `send_chat_msg(..., insert_immediately=True)`，正在执行群聊或协作任务的 Agent B 能在下一个安全边界按序收到该消息（含排在前面或后面的未读普通消息）。
- [ ] **非支持场景优雅降级**：Agent 对群聊、操作者控制房或不支持 `host_managed_turn_loop` 的目标 Agent 传 `insert_immediately=True` 时，消息自动降级为 `insert_immediately=False` 正常送达，工具返回 `success=True` 及说明文案。
- [ ] **空闲唤醒**：目标 Agent 空闲时，收到其他 Agent 发来的单聊加急消息能立即唤醒房间并启动消费。
- [ ] **双 AI 单聊尾唤醒准确**：在 `[Agent A, Agent B]` 单聊中，若 Agent B 轮次执行期间收到 Agent A 的普通未读消息，B 结束当前轮次切回空闲时，系统精准唤醒 Agent B 开启下一轮读取，不会误唤醒发送方 Agent A。
- [ ] **中途升级与界面展示**：双 Agent 单聊中，未读消息展示在底部浮动待读区（支持操作者点击「立即引导」升级）；接收方 AI 读取后移入主消息流，加急消息保留 `⚡` 标记。
