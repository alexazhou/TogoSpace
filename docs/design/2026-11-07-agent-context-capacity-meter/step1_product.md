# Agent 上下文容量实时进度条 - 产品设计

> 关联文档：[技术设计](./step2_technical.md) | 关联技术标准：[Token Compaction 技术规范](../../tech/04_agent/token_compaction.md)

## 1. 背景与目标

### 1.1 现状与痛点
在多 Agent 长程对话和复杂协作任务中，Agent 的历史上下文（Tokens）会随着交互持续积累。虽然系统底层具备自动压缩机制（Token Compaction，达到约 85% 上下文上限时触发智能摘要与历史截断），但在前端视角下：
- **容量黑盒**：用户无法直观了解当前 Agent 的上下文窗口到底用了多少，距离上限与压缩警戒线还有多远；
- **排障不便**：当 Agent 出现长文本推理变慢、偶尔因上下文超长发生重试时，缺乏立即可见的上下文指标支撑排查；
- **被动刷新**：旧模式往往需要用户刷新页面或手动拉取接口，无法感受长轮次任务中 token 动态消耗与压缩释放的真实过程。

### 1.2 本次目标
- **极简可视化**：在 Agent 活动卡片（`AgentActivityDialog`）的头像卡片下方，提供一个克制、美观、低视觉干扰的微型容量比例进度条；
- **主动治理（手动 Compact）**：支持用户在感知到上下文偏大时，主动一键触发「手动压缩（Compact）」，提前清理冗长对话历史，释放上下文空间；
- **纯实时推送**：基于 WebSocket 事件总线，当 Agent 发生推理消费、工具执行或触发 Compact 压缩时，前端自动接收增量事件并平滑过渡更新，**无需任何页面刷新或轮询**；
- **健康度警示**：结合系统的 Compact 触发阈值，以三级语义色温（日常 / 充盈 / 即将压缩）为用户提供直观感知。

## 2. 交互与视觉设计

### 2.1 摆放位置
进度条紧贴放置在 **Agent 活动弹窗左侧舞台区域（Stage）的头像卡片（`AgentCardBase`）正下方、状态指示器（`agent-status-panel`）上方**。
- 宽度与头像卡片完全一致（`132px`）；
- 上下间距均匀（距离头像卡片底边 `8px`，距离状态标签 `6px`），构成统一的实体信息层级：
  `[卡片身份识别] -> [上下文资源负荷] -> [在线/忙闲状态] -> [操作指令]`。

```text
┌─────────────────────────────────┐
│        [ Agent 头像卡片 ]        │
│           (宽 132px)            │
└─────────────────────────────────┘
 ┌───────────────────────────────┐
 │ 上下文          28%   [压缩]  │  ← 极简排版 + 微型压缩按钮 (Compact)
 │ ▰▰▰▰▰▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱▱ │  ← 4px 细长圆角胶囊条
 └───────────────────────────────┘
          ● 空闲 (IDLE)
   [ 停止 ]  [ 打开房间 ]
```

### 2.2 视觉排版与微动效
1. **排版布局**：
   - 上行：左侧微标「上下文」（`t('agent.contextUsage')`），中间紧随百分比（如 `28%`），右侧为微型「压缩」操作按钮（`t('agent.compact')`）；文字颜色为次级文本色（`var(--text-secondary)`），百分比采用中等粗细半等宽数字；
   - 下行：高度为 `4px` 的细胶囊轨道（`border-radius: 999px`），底轨使用柔和背景（`var(--surface-input)` 或带有微弱边界感的设计系统色）；
   - 内部滑块采用 `transition: width 300ms cubic-bezier(0.4, 0, 0.2, 1)`，使推理完成后的增长和压缩后的回落具备舒适的机械回弹质感。
2. **状态颜色分级（语义色温）**：
   - **日常健康区间（< 70%）**：主题色 / 柔和微蓝紫（`var(--accent)`），代表安全富余；
   - **充盈警戒区间（70% ~ 85%）**：琥珀黄（Amber / `#f59e0b`），提示上下文即将达到系统触发压缩的临界点；
   - **高危 / 极高区间（> 85%）**：橙红（Danger / `#ef4444`），表示当前已处在压缩触发线上，本轮或下轮即将生成压缩摘要。

### 2.3 手动 Compact（一键压缩）交互
1. **触发入口**：
   - 进度条右上角的微型操作按钮「压缩」（或图标按钮 `🗜️` / 文本按钮 `[压缩]`）；
   - 点击时按钮进入 loading 旋转状态（`compacting = true`），并触发后端压缩；
2. **执行与反馈**：
   - 成功后弹出轻量全局提示 `t('agent.compactSuccess', '上下文压缩已完成')`；
   - 进度条在 WebSocket 实时事件驱动下自动滑落至压缩后的新比例（如从 80% 平滑滑落至 18%）；
   - 在中间主活动面板（Activities Tab）中，会即时追加一条 `COMPACT` 类型的活动卡片，记录压缩明细与耗时；
3. **禁用与可用态管控**：
   - **执行中保护（ACTIVE）**：当 Agent 正在执行复杂任务（状态为 `ACTIVE`）时，禁用按钮并提示「Agent 正在工作中，暂不支持手动压缩」，避免在活跃 Turn 循环内并发修改对话历史；
   - **无可压缩内容**：若当前对话历史仅包含最新开局消息或首条 System Prompt（无可提取上下文），按钮置灰或点击提示「当前无足够可压缩的历史消息」。

### 2.3 悬浮详情（Tooltip）
鼠标悬停在进度条容器上时，弹出原生或轻量 Tooltip，展开精确的 token 统计明细：
```text
当前上下文: 36,420 / 128,000 (28.5%)
压缩阈值: 108,800 (85.0%)
```

## 3. 核心业务规则与数据定义

### 3.1 指标计算规则
1. **分母（总容量 / 窗口上限 `total_tokens`）**：
   - 取自当前 Agent 所绑定模型的生效配置 `context_window_tokens`；
   - 优先级遵循系统配置规范：用户自定义模型配置 > 内置模型默认映射表 > 平台默认兜底值（`131,072`）。
2. **分子（当前已用容量 `used_tokens`）**：
   - **内存活跃态**：从 Agent 内存 `AgentHistoryStore` 的未压缩上下文消息序列，通过系统内置的估算与实际 Usage 综合得出；
   - **离线 / 初始加载态**：读取持久化历史中最新一轮会话有效消息集；
   - 包含：系统提示词（System Prompt）、未被压缩的所有历史轮次上下文（User / Assistant / Tool 结果）。
3. **压缩阈值（`compact_trigger_tokens`）**：
   - 依据 `floor((context_window - reserve_output) * compact_trigger_ratio)` 计算（默认比率通常为 0.85）；
   - 前端色温判断以该值为基准。

### 3.2 动态更新场景与生命周期
| 业务场景 | 容量变化表现 | 进度条响应 |
|---|---|---|
| **首屏打开弹窗** | 随详情接口（`GET /agents/{id}.json`）返回初始静态快照 | 瞬间就绪渲染初始百分比，无骨架屏闪烁 |
| **Agent 推理完成（LLM Infer）** | 实际 `usage.prompt_tokens` 产生，对话历史新增回复 | 进度条平滑增长至新百分比 |
| **执行 Compact 压缩** | 历史被裁剪归纳为单条摘要，大量旧消息释放 | 进度条从高位（如 85%）迅速回落至低位（如 15%~20%） |
| **新消息到达 / 轮次推进** | 上下文注入了新的待处理消息 | 后端更新并广播，进度条小幅微增 |

## 4. 边界与特殊场景处理

1. **特殊 Agent（Operator / System）**：
   - 人类操作员或系统级虚拟 Agent 不消耗 LLM 上下文，不渲染该进度条组件。
2. **零历史记录（全新建成员）**：
   - 进度条显示为 `0%` 或初始 System Prompt 基础占比（如 `< 1%`），保持常态展示。
3. **模型配置在线热更新**：
   - 用户在系统设置中调整了该模型的 `context_window_tokens` 时，广播将同步携带最新分母，前端自适应缩放比例。
4. **长短轮次超界保护**：
   - 百分比通过 `Math.min(100, Math.max(0, ratio))` 兜底，防止极端异常下进度条溢出容器。
